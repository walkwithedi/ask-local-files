# ask-local-files：找文件问 AI

[English](README.md)

在不能装软件的电脑上，拿本地文件问大模型。只需要 Python 3 和浏览器，接任何 OpenAI 兼容接口，回答附原文摘句并自动核对。

- 零安装：只用 Python 3 标准库，双击「双击运行」或运行一条命令，在浏览器里操作；页面不从网络加载任何东西。
- 自己选文件，整篇发送：在添加的文件夹里按文件名找出文件，选几个连同问题发给模型，不建向量库、不切块检索。
- 摘句核对：要求模型每个结论附原文摘句，回答结束后逐条核对摘句是否真在文件里，找不到的标出来，减少编造。
- 记忆：提问时选过的文件和核对通过的结论记在本机，之后提问时自动参考，不选文件也能问以前用过的内容；可关闭、查看和清空。
- 没有模型也能用：找文件、预览，把取出的文字连同摘句要求复制或保存下来，带到别处的 AI 去问。
- 只连你配置的模型接口：公司内网的模型网关、自建的 vLLM、公有云 API 都可以；本机运行的 llama-server 或 Ollama 自动发现。已在用 OpenCode 时自动读取它的模型配置。

页面为中文。

## 运行环境要求

- Python 3.8 及以上，支持 `fetch` 与流式读取的浏览器（较新的 Firefox 或 Chromium）。Linux 下可双击运行，其他系统用命令行启动。
- 可选：`pdftotext`（poppler-utils），没有时读不了 pdf，其他格式不受影响。
- 一个 OpenAI 兼容的模型接口（接口地址、模型名，需要时加 AK），或本机运行的 llama-server、Ollama。不需要访问其他网络，不需要安装第三方包。

## 使用方法

从 Releases 下载 `ask-local-files-v<版本>.zip` 并解压，双击「双击运行」，或运行 `python3 ask_local_files.py`。

页面宽度 900px 及以上时铺满浏览器窗口，分两栏：左栏「找文件」「已选」，右栏「问 AI」占满其余宽度和高度，约 3:7；窄屏为单列。「找文件」「已选」「问 AI」都可以点标题收起成一行，标题旁写摘要，收起状态记在本浏览器；宽屏下一栏全部收起时另一栏占满宽度；窄屏开始对话后「找文件」自动收起，点标题展开。「＋ 新对话」在同一窗口里开新的对话标签，最多 8 个，各自选文件、各自对话；点标签上的「×」直接关闭，不确认，正在生成的回答随之停止，未保存的问答随之清空。

1. 添加文件夹：第一次使用时自动展开「管理文件夹」。填文件夹路径（绝对路径、`~/` 开头，或从文件管理器地址栏复制的本机 `file:///` 地址）点「添加」，可以添加多个；也可以点「选择……」在系统的选择窗口里选（用 zenity、kdialog 或 tkinter 中找得到的一个）。输入路径时下拉列出子文件夹，下方给出本机存在的常用位置。添加后在后台扫描，扫描期间就能搜索。
2. 找文件分「搜索」「浏览文件夹」两个标签页，方向键可切换，打开页面时停在上次用的标签（记在本浏览器，读不到时为「搜索」）。标签右边的「排序」对两个标签页都有效：最新在前（默认）、最旧在前（按最后修改时间）、名称 A→Z、名称 Z→A（不区分大小写），选择记在本浏览器；先按所选排序再取显示上限。
   - 搜索：输入文件名或路径里的字，边打字边出结果。多个关键字用空格分开，必须全部命中；扩展名框里填 `docx pdf` 只看这几类。勾上「正则表达式」时整个搜索框按一个正则表达式（Python 写法，不区分大小写）匹配。结果按所选排序，最多 300 个；点结果里的文件夹名跳到「浏览文件夹」。按回车加入第一个结果，方向键在结果间移动。
   - 浏览文件夹：从已添加的文件夹开始逐层查看，先列子文件夹（按名称，写明各层共含多少文件），再列本层文件（按所选排序，最多 300 个）。进入某个文件夹后可以「全部加入」它和各层子文件夹里读得了的文件。
   - 读不了的格式写明原因；压缩包等读不了的文件给「打开文件夹」，其余每个文件（含已选）有一个文件夹图标按钮（「在文件夹中显示」）。两者都在文件管理器里打开所在文件夹并选中文件：先用 `org.freedesktop.FileManager1.ShowItems`（`gdbus`，没有时 `dbus-send`），再试 `peony --show-items`、`nautilus --select`、`caja --select`，最后用 `xdg-open` 或 `gio open` 只打开文件夹；都打不开时写出路径并给「复制路径」。
   - 「从列表移除」只把一项从当前列表拿掉，不删文件、不影响已选，换关键字、进别的文件夹或点「刷新」后恢复。
   - 忽略 Markdown 文件（默认勾上，记在设置里）：搜索和浏览都不列 .md、.markdown 文件，文件数、「全部加入」「加入前 N 个」也不算它们，只有这类文件的子文件夹不列；扩展名框里明确填了 md 或 markdown 时照列。已选里已有的不受影响，索引不变。
   - 按文件名去重（默认勾上）：同名文件只列修改时间最新的一个，旁边写「另有 N 个同名」，点开可看其余同名文件并单独加入。同名指不区分大小写、扩展名相同，并且去掉一个副本标记（如「 (1)」「（2）」「 - 副本」「 copy」）后文件名相同。只影响列表和「全部加入」，不改索引，不动文件。
3. 已选：点「加入」，一次最多 50 个文件；列表里（去重与移除之后）少于 50 个时可以「全部加入」，只加读得了且还没加入的文件。可加入的多于 10 个、30 个时分别出现「加入前 10 个」「加入前 30 个」，按所选排序取（浏览时含各层子文件夹），已选还能加的不足 N 个时不可点。已选按「1.」「2.」编号，与发给模型的「文件 N」一致。可以「预览」取出的文字、「移除」单个文件、「清空已选」；「复制已选择的文件路径」把已选文件的完整路径一行一个复制下来，可粘贴给「问 AI」里的 OpenCode 等智能体直接处理这些文件，复制失败时在状态行列出路径供手动复制。开始对话后再改动文件清单，直接开始新对话，并在状态行说明。
   「复制全部文字」「保存全部文字」（存成 `找文件问AI-文字-年月日-时分.md`）给出与发给模型相同的系统消息：摘句要求加上每个文件的全文（按「===== 文件 N：路径 =====」），不带 skill 说明，不受字数上限限制，贴进任何 AI 后接着写问题即可；取不出文字的文件跳过并写明个数。有没有模型都能用。
4. 问 AI：没有可用模型（OpenCode 配置、本机模型和自定义接口都没有）时，「问 AI」只留一行说明和「模型设置」，「找文件」占满宽度；填齐自定义接口后恢复。有模型时在输入框上方选模型，需要时选一个 skill（见下方「skill」），写要 AI 做什么，点「发送」或按 Enter（Ctrl+Enter 也可以），Shift+Enter 换行。回答逐字显示，按常见 Markdown 排版，可以接着追问，追问带着前面的问答和同一批文件。生成中可以「停止」；中断时保留已收到的部分，标「（回答不完整）」，并给「继续」（从断处接着写）和「重新生成」（用原问题重新请求）。
5. 摘句核对：模型须只依据所选文件回答，每个结论后附「（文件 N：「原文摘句」）」，找不到依据的写「所选文件中未找到」。摘句逐字照抄，一句以内、不超过 50 字，不跨段落、不跨表格格子；规则写在文件之前，文件之后再重申要点。回答先给结论再分点，可用 Markdown；选了 skill 时按 skill 的格式。确有需要时模型可在末尾另起「文件外补充（未核对）：」一段，这一段不核对、不记入记忆。回答结束后逐条核对摘句（忽略空白差异，省略号两侧分开核对），找不到的摘句列在回答下方；整条回答没附摘句时也会提示。这些提示一并写进保存的对话。
6. 每条回答可以「复制」「保存为 Word」；「保存对话」把文件清单和全部问答存成 `找文件问AI-年月日-时分.md`；「清空对话」点了直接清空，之后的提问是新对话。
7. 字数上限：页面上一直写着将发送到哪个接口主机、哪个模型、几个文件和字数。文件和对话合计超过「发送字数上限」（默认 10 万字）时先不发送，可以移除文件、调高上限，或「仍然发送」（按比例截断文件部分）。
8. 接口出错时写明原因和下一步：AK 无效或过期（401、403）、接口地址或模型名不对（404）、内容过长、请求太频繁或额度用完（429）。

支持的格式：

- 纯文本类直接读取：txt、md、csv、tsv、log、json、xml、yaml、ini、conf、sql 和常见代码文件，编码按 UTF-8、GB18030 识别，单个文件最多 20 MB；html、htm 去掉标签后取文字。
- docx、xlsx、xlsm、pptx、eml、pdf 由 `doc2kb_core.py` 转成文字；pdf 需要 `pdftotext`，扫描件取不出文字。
- 旧版 doc、xls、ppt（Office 97 及以后）同样由 `doc2kb_core.py` 取文字和表格；wps、et、dps 分别按 doc、xls、ppt 试读。有密码保护、更早版本或损坏的文件提示先另存为 docx、xlsx 或 pptx。
- 压缩包不读取，提示先解压，可点「打开文件夹」。其他扩展名按纯文本尝试，是二进制文件时提示不支持。
- 每个文件取出的文字开头先写路径、文件名、修改时间，文档里记录了作者时再写作者（和与作者不同的最后修改者），随正文一起发给模型。

## 索引与缓存

- 只索引添加的文件夹，跳过以 `.` 开头的文件和文件夹、`node_modules`、`__pycache__`，不跟随指向文件夹的链接；读不了的文件夹跳过并在状态里列出。
- 只匹配文件名和路径，不看文件内容。索引缓存在 `~/.cache/ask-local-files/index.json`（权限 600），启动即可搜索，后台只重扫修改时间变了的文件夹。点「刷新」立即检查，「重建索引」全部重扫。

## 模型接口与隐私

- 有 OpenCode 配置（`~/.config/opencode/opencode.jsonc` 或 `opencode.json`）时，列出其中带 `options.baseURL` 和 `options.apiKey` 的服务商下的全部模型；apiKey 可写成 `{env:变量}` 或 `{file:路径}`，服务商的 `headers` 一并带上。
- 本机模型：见下方「本机模型」。
- 也可以在「模型设置」里填接口地址、模型名和 AK，作为一项可选模型，「测试连接」可检查是否连通。接口不需要鉴权时 AK 可以不填；接口不在本机时，「将发送到」的主机后标「（未鉴权）」。设置存在 `~/.config/ask-local-files/config.json`（权限 600）。AK 不发给页面，日志不记 AK 和文件内容。
- 模型接口超过 120 秒没有新内容即判为失败；接口在本机（127.0.0.1、localhost、::1）时放宽到 900 秒，且不走代理。
- 「复制全部文字」「保存全部文字」不经过模型接口，文字只写进剪贴板或下载的文件。
- 请求按 OpenAI 兼容的 `POST <接口地址>/chat/completions` 流式发送：系统消息写明摘句要求和所选文件，按「===== 文件 N：路径 =====」附上取出的文字，后面是对话。
- 文件文字和对话会发给你选的模型接口，请只选你有权交给该接口处理的文件。记忆打开时（默认），提问时选过的文件取出的文字和核对通过的结论存在本机的记忆文件里（见下方「记忆」）；关掉记忆后取出的文字只放在内存里，不写硬盘。对话只留在页面上，需要时点「保存对话」。
- 用到记忆时，系统消息在已选文件之后按「===== 文件 N：路径（来自记忆，节选）=====」附上记忆里找出的以前结论与原文段落，并写明以前的结论只作线索、摘句须从原文节选里照抄。

## 记忆

- 作用：提问时选过的文件，取出的文字按段落记下；回答里附了原文摘句且核对通过的句子，去掉出处后作为一条「结论」连同原句、文件和提问记下。之后提问时按问题找出相关的以前结论和原文段落一起发给模型，所以不选文件也能问以前用过的内容；同一结论被得出的次数越多越靠前。
- 存放：`~/.local/share/ask-local-files/memory.sqlite`（`XDG_DATA_HOME` 生效；文件权限 600，文件夹 700），只存取出的文字和原路径，不存原文件，各对话标签共用。库文件打不开或损坏时改名留存，另建新的。
- 检索：问题按标点、空格和常见虚词切成关键字，SQLite 带 FTS5 时用全文索引，没有时逐条匹配；按命中的关键字数排序，结论另按被得出的次数和新近程度加分。已选文件里的内容不重复给。
- 与文件一致：取用前检查记忆里的文件，修改时间或大小变了就重新取文字，原句已不在新文字里的结论和主题页要点标为待复核，不再拿去参考，等下次更新时由模型按新文字改写；文件不在了，它的段落、结论和要点一起忘掉，删光要点的主题页一并删除。
- 字数：没选文件时记忆可用发送字数上限扣除 skill 说明与对话后的全部余量；选了文件时至多占这部分余量的三分之一，且只用文件用不完的字数。
- 「参考记忆」：在 skill 下方，默认勾选。勾选时可以不选文件直接提问；用到记忆的回答上方写明参考了几条结论、几段原文，可点开查看。记住了结论的回答旁有「不对」，点了忘掉这条回答记下的结论，之后不再记入。
- 记忆设置：独立面板，由「参考记忆」旁的「记忆设置 ▸」展开或收起（与「模型设置」一样），每次打开页面时收起。回答下方的「已记住 N 条结论」（同时展开「查看记忆」）和首次提示里的「记忆设置」也会展开它，滚到面板并把焦点移到那里。记忆关闭时「参考记忆」隐藏，「记忆设置」保留，可以重新打开记忆。「查看记忆」按钮用主色。页头介绍里也写明了记忆的用法。
- 管理：「记忆设置」里有总开关（默认开）、已记住的文件、结论、主题页与待更新项数、「查看记忆」（可搜索、删除一页主题页或单条结论、忘掉一个文件）和「清空记忆」。关掉后不再记入也不再参考，已记住的保留。
- 更新（参考 LLM Wiki 的做法）：模型把记忆维护成一组可积累的主题页。新记入或改过的结论、内容变了的文件先排进更新队列，回答时不多调模型。更新时把队列里的内容连同相关主题页和结论分批发给所选模型（每批不超过发送字数上限，且至多 12,000 字、40 条结论），由它：1. 把结论按主题整理成主题页（标题和要点，每条要点带出处文件和原句）；2. 合并重复（次数相加）、以新代旧、删除不再成立的；3. 文件改过的按新文字改写结论并换上新原句，改不了的删除。回答须是约定的 JSON；要点和改写后的结论写入前按文件当前文字核对原句，核对不过或「不对」过的不写入；看不懂的回答这一批留在队里。提问时主题页要点排在最前（写作「主题：要点」），其次是结论，同一原句只用一次。
- 「更新记忆」：在「记忆设置」里，先处理队列，再把全部结论体检一遍，显示阶段与第几批；「停止」后正在处理的那一批不写入；点「退出」时等它结束再退出。
- 「空闲时自动更新」：默认勾选，记在设置里。工具开着、没有回答在生成、且 10 分钟没有提问时，用所选模型处理更新队列；一提问或退出就停下，正在处理的那一批不写入。模型出错时停下这一轮，原因写在「记忆设置」里，下次空闲再试。
- 更新记录：「更新记录」列出最近 20 次更新（手动、自动都算）的时间、改动数和改动说明；最近一次旁有「撤销」，恢复这次更新前的结论和主题页，可逐次往回撤销。已不在记忆里的文件、「不对」过的结论不恢复，更新队列不恢复。「清空记忆」也清空队列和更新记录。
- 发送：更新会把结论、原句、相关主题页和改过文件的新文字发给所选模型，与提问是同一个接口；不想自动发送可取消「空闲时自动更新」。记忆库就地升级，已有内容保留。
- 容量：记忆里的文字超过 200 MB 时，先忘掉最久没用的文件及其结论。记忆出错只写日志，提问照常进行。

## 本机模型

- 打开页面、展开「模型设置」或点「重新查找」时，探测本机 `127.0.0.1:8080`（llama-server）与 `127.0.0.1:11434`（Ollama）的 `/v1/models`，每个模型列为「模型名（本机 llama-server）」或「模型名（本机 Ollama）」，请求不带 AK。服务在页面打开后才启动或中途停掉时，点「重新查找」更新列表。
- 发送字数上限按模型上下文折算：llama-server 读 `/props` 的 `n_ctx`，Ollama 读 `/api/ps` 里已加载模型的 `context_length`（尚未加载时按 `OLLAMA_CONTEXT_LENGTH`，没有时 4096）；1 token 按 1 字计，留四分之一给回答，取「上下文 × 0.75」与设置值中较小的。读不到上下文时只按设置值。
- skill 照常可选；llama-server 要加 `--jinja` 启动才接受工具调用。
- 本工具不安装、不启动模型服务，例如 `llama-server -m 模型.gguf --port 8080 --jinja`、`OLLAMA_CONTEXT_LENGTH=16384 ollama serve` 需另行运行。

## skill

skill 是一个文件夹，内有 `SKILL.md`：开头两行 `---` 之间写 `name:` 和 `description:`，其后是给模型的说明；文件夹里还可以放参考文件和 `.py`、`.sh` 脚本（OpenCode 的 skill 格式）。「skill」下拉框列出工具目录 `skills/` 里预装的和 `~/.config/opencode/skills/` 里自建的，默认「不用 skill」。选了 skill 时可以不选文件，也可以不写问题直接发送；每条回答标明用了哪个 skill。

- skill 正文放在系统消息最前面，计入字数上限。选了文件时照常要求附原文摘句；依据脚本输出或参考文件得出的内容标「（脚本输出）」。
- skill 有参考文件或脚本时，请求按 OpenAI 兼容的函数调用（`tools`）附上工具，模型按需调用：
  - `read_skill_file`：读 skill 文件夹里的文本文件，单个最多 2 万字。
  - `run_script`：运行 skill 文件夹里的 `.py`（用运行本工具的 Python）或 `.sh`（用 bash），参数逐个传入、不经 shell。脚本从环境变量拿到 `ASK_FILES`（已选文件的路径，换行分隔）、`ASK_ROOTS`（已添加的文件夹）、`ASK_OUT`（本次运行的输出目录，写进去的文件可在页面上保存）、`ASK_WORK`（本问的工作目录）和 `ASK_TOOL_DIR`（工具目录，可借用 `doc2kb_core.py`）。
  - `write_work_file`：有脚本的 skill 才提供，把长内容写进 `ASK_WORK` 供脚本读取，单个文件最多 50 万字。工作目录每问新建，回答结束时删除。
  - 路径不能超出 skill 文件夹或工作目录（含经链接跳出）。
- 限制：脚本自动运行，不逐次确认；单次最多 60 秒；每问最多 5 次读取或运行、10 次写入；交给模型的工具结果最多 2 万字。点「停止」同时终止正在运行的脚本。模型接口不支持函数调用时写明原因，可改选只有说明的 skill 或换模型。
- 选用带脚本的 skill 即允许脚本以当前用户身份运行，能读写当前用户能访问的文件；只放来源可信的 skill。脚本输出会发给模型接口。

预装 skill：

| 名称 | 页面显示 | 用途 | 脚本 |
| --- | --- | --- | --- |
| `summarize-meeting` | 会议纪要 | 会议转写或记录 → 日期、参会人、要点、决定事项、待办、未决问题 | 无 |
| `doc-compare` | 文档对比 | 逐行比对两份已选文件，列出新增、删除、修改并归纳实质变化，可另存左右对照的 HTML 报告 | `scripts/compare.py` |
| `office-gen` | 生成 Word 与 Excel | 把整理好的内容生成 docx 或 xlsx，生成的文件可保存 | `scripts/make_docx.py`（Markdown → docx）、`scripts/make_xlsx.py`（JSON → xlsx） |
| `prompt-optimize` | 提示词优化 | 把原始提示词重写为简洁、明确、按编号分层的提示词 | 无 |
| `clarify-needs` | 需求澄清 | 任务描述笼统时先逐个提问摸清需求，问完给出需求摘要，确认后再执行 | 无 |

预装脚本只用 Python 3 标准库，也可以在终端单独运行（按上面的环境变量传入文件），带 `--help` 与 `--log-level`。`summarize-meeting` 原样复制自 [phuryn/pm-skills](https://github.com/phuryn/pm-skills)（MIT License），文件夹里附许可文件与 `UPSTREAM.md`。

## 双击运行与退出

首次双击时，文件管理器可能提示信任或询问运行方式，选允许运行即可；不允许时在「属性」→「权限」里勾选「允许作为程序执行」。放到桌面请用链接：`ln -s "$PWD/双击运行.desktop" ~/桌面/找文件问AI.desktop`，不要复制。

双击时优先用 Chromium 系浏览器（含奇安信、360、统信等国产 Chromium 系浏览器）的应用窗口模式（`--app`）打开，不显示地址栏；命令不在 PATH 里时按这些浏览器的桌面文件找到程序；都找不到时用默认浏览器的普通窗口。

服务只监听 127.0.0.1 的随机端口，网址带一次性令牌并校验 Host、Origin。点右上角「退出」立即结束；关闭页面约 5 秒后自动退出，页面挂在后台不影响；有回答正在生成、脚本在运行或「更新记忆」正在进行时等它结束再退出；空闲时自动更新不拖住退出。日志写在程序目录下的 `ask_local_files.log`（目录不可写时写到 `~/.cache/ask-local-files/`）。

命令行：`python3 ask_local_files.py [--no-browser] [--no-app] [--log-level DEBUG|INFO|WARNING|ERROR]`，`--no-browser` 只打印网址，`--no-app` 用默认浏览器的普通窗口打开；日志级别默认 WARNING，可由环境变量 `LOG_LEVEL` 覆盖。

测试：`python3 -m unittest discover -s tests`；装有 Playwright 时 `node --test tests/ui.test.js`。
