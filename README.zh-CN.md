# ask-local-files：资料管家

[English](README.md)

在不能装软件的电脑上，拿本地文件问大模型。只需要 Python 3 和浏览器，接任何 OpenAI 兼容接口，回答附原文摘句并自动核对。

- 零安装：只用 Python 3 标准库，双击「资料管家」或运行一条命令，在浏览器里操作；页面不从网络加载任何东西。
- 自己选文件，整篇发送：在添加的文件夹里按文件名找出文件，选几个连同问题发给模型，不建向量库、不切块检索。
- 摘句核对：要求模型每个结论附原文摘句，回答结束后逐条核对摘句是否真在文件里，找不到的标出来，减少编造。
- 知识库：提问时选过的文件和核对通过的结论记在本机，之后提问时自动参考，不选文件也能问以前用过的内容；可关闭、查看和清空。
- 自动收录的文件夹：给添加的文件夹勾选「自动收录到知识库」，其中的文件在后台收录到知识库，由模型抽出带原句核对的结论并整理成互相关联的主题，可保存为用 Obsidian 打开的 Markdown。
- 没有模型也能用：找文件、预览，把取出的文字连同摘句要求复制或保存下来，带到别处的 AI 去问。
- 只连你配置的模型接口：公司内网的模型网关、自建的 vLLM、公有云 API 都可以；本机运行的 llama-server 或 Ollama 自动发现。已在用 OpenCode 时自动读取它的模型配置。

页面为中文。

## 运行环境要求

- Python 3.8 及以上，支持 `fetch` 与流式读取的浏览器（较新的 Firefox 或 Chromium）。Linux 下可双击运行，其他系统用命令行启动。
- 可选：`pdftotext`（poppler-utils），没有时读不了 pdf，其他格式不受影响。
- 一个 OpenAI 兼容的模型接口（接口地址、模型名，需要时加 AK），或本机运行的 llama-server、Ollama。不需要访问其他网络，不需要安装第三方包。

## 使用方法

从 Releases 下载 `ask-local-files-v<版本>.zip` 并解压到以后不再挪动的文件夹（之后的新版在这里原地替换，见下方「升级」），双击「资料管家」，或运行 `python3 ask_local_files.py`。

页面宽度 900px 及以上时铺满浏览器窗口，分两栏：左栏「知识库」卡片（「文件」「概览」「主题与结论」三个标签，见下方「知识库」）和「已选」，右栏「问 AI」占满其余宽度和高度，约 3:7；窄屏为单列。「知识库」「已选」「问 AI」都可以点标题收起成一行，标题旁写摘要，收起状态记在本浏览器；宽屏下一栏全部收起时另一栏占满宽度；窄屏开始对话后「知识库」自动收起，点标题展开。页头最前有「跳到提问框」链接（获得键盘焦点时显示），Ctrl+L 随时聚焦提问框。「＋ 新对话」在同一窗口里开新的对话标签，最多 8 个，各自选文件、各自对话；点标签上的「×」直接关闭，不确认，正在生成的回答随之停止，未保存的问答随之清空。

1. 添加文件夹：第一次使用时「知识库」卡片停在「概览」，点「添加文件夹」（或「问 AI」引导第 1 步）切到「文件」标签并打开「管理文件夹」。「管理文件夹」是占满大半个窗口的对话框（窄屏占满屏幕），打开期间页面其他部分不能操作，点「完成」或按 Esc 关闭，焦点回到「管理文件夹」按钮，文件列表随之刷新；还没有文件夹时进「文件」标签不自动打开它，列表里给「添加文件夹」。填文件夹路径（绝对路径、`~/` 开头，或从文件管理器地址栏复制的本机 `file:///` 地址）点「添加」，可以添加多个；也可以点「选择……」在系统的选择窗口里选（用 zenity、kdialog 或 tkinter 中找得到的一个）；等待时状态区显示已等的秒数，10 秒后提示窗口可能在浏览器后面，旁边的「取消」可关掉选择窗口，不设自动超时。输入路径时下拉列出子文件夹，下方给出本机存在的常用位置。添加后在后台扫描，扫描期间就能搜索。
2. 找文件在「知识库」卡片的「文件」标签里，是一个视图：顶部是路径导航（「全部」为所有已添加的文件夹），下面是搜索框（框内「×」清除）和扩展名框。打开页面回到上次所在的文件夹（记在本浏览器，文件夹已不在时回到「全部」）。「刷新」「管理文件夹」旁的「选项 ▸」默认收起（展开与否记在本浏览器，有不是默认值的项时按钮写「选项（N 项已改）」），里面是「排序」和「按文件名去重」「正则表达式」「忽略 Markdown 文件」三个勾选框。「排序」可选最新在前（默认）、最旧在前（按最后修改时间）、名称 A→Z、名称 Z→A（不区分大小写），记在本浏览器；先按所选排序再取显示上限。
   - 两个框都空时列出当前文件夹：先列子文件夹（按名称，写明各层共含多少文件），再列这个文件夹及各层子文件夹里的文件，与在这里空关键字搜索相同：按所选排序，最多 300 个，每个文件写出所在文件夹（点它进入）；修改时间相同的按路径排先后。进入某个文件夹后可以「全部加入」它和各层子文件夹里读得了的文件。
   - 任一框里有字时，在当前文件夹及各层子文件夹里搜（在「全部」时搜全部），边打字边出结果。多个关键字用空格分开，必须全部命中文件夹以下的相对路径；扩展名框里填 `docx pdf` 只看这几类。勾上「正则表达式」时整个搜索框按一个正则表达式（Python 写法，不区分大小写）匹配。结果按所选排序，最多 300 个；点路径导航或结果里的所在文件夹时保留关键字，在那个文件夹里重搜。按回车加入第一个结果，方向键在结果间移动。
   - 读不了的格式写明原因；压缩包等读不了的文件给「打开文件夹」，其余每个文件（含已选）有一个文件夹图标按钮（「在文件夹中显示」）。两者都在文件管理器里打开所在文件夹并选中文件：先用 `org.freedesktop.FileManager1.ShowItems`（`gdbus`，没有时 `dbus-send`），再试 `peony --show-items`、`nautilus --select`、`caja --select`，最后用 `xdg-open` 或 `gio open` 只打开文件夹；都打不开时写出路径并给「复制路径」。
   - 「从列表移除」只把一项从当前列表拿掉，不删文件、不影响已选，换关键字、进别的文件夹或点「刷新」后恢复。
   - 忽略 Markdown 文件（默认勾上，记在设置里）：搜索和浏览都不列 .md、.markdown 文件，文件数、「全部加入」「加入前 N 个」也不算它们，只有这类文件的子文件夹不列；扩展名框里明确填了 md 或 markdown 时照列。已选里已有的不受影响，索引不变。
   - 按文件名去重（默认勾上）：同名文件只列修改时间最新的一个，旁边写「另有 N 个同名」，点开可看其余同名文件并单独加入。同名指不区分大小写、扩展名相同，并且去掉一个副本标记（如「 (1)」「（2）」「 - 副本」「 copy」）后文件名相同。只影响列表和「全部加入」，不改索引，不动文件。
3. 已选：点「加入」，一次最多 50 个文件；列表里（去重与移除之后）少于 50 个时可以「全部加入」，只加读得了且还没加入的文件。可加入的多于 10 个、30 个、50 个时分别出现「加入前 10 个」「加入前 30 个」「加入前 50 个」，按所选排序取（在文件夹里时含各层子文件夹），已选还能加的不足 N 个时不可点。已选按「1.」「2.」编号，与发给模型的「文件 N」一致。可以「预览」取出的文字、「移除」单个文件、「清空已选」；「复制已选择的文件路径」把已选文件的完整路径一行一个复制下来，可粘贴给「问 AI」里的 OpenCode 等智能体直接处理这些文件，复制失败时在状态行列出路径供手动复制。开始对话后再改动文件清单，直接开始新对话，并在状态行说明。
   「复制全部文字」「保存全部文字」（存成 `资料管家-文字-年月日-时分.md`）给出与发给模型相同的内容（只是没有问题）：回答语言与摘句要求，每个文件的全文放在 `<document index="N"><source>路径</source><document_content>…</document_content></document>` 里，最后重申要点；不带 skill 说明，不受字数上限限制，贴进任何 AI 后接着写问题即可；取不出文字的文件跳过并写明个数。有没有模型都能用。
4. 问 AI：没有可用模型（OpenCode 配置、本机模型和自定义接口都没有）时，「问 AI」只留一行说明和「模型设置」，排到左栏「知识库」卡片下方，「已选」移到右栏；填齐自定义接口后恢复。有模型时在输入框上方选模型，需要时选一个 skill（见下方「skill」），写要 AI 做什么，点「发送」或按 Enter（Ctrl+Enter 也可以），Shift+Enter 换行。回答逐字显示，按常见 Markdown 排版，可以接着追问，追问带着前面的问答和同一批文件。生成中可以「停止」；中断时保留已收到的部分，标「（回答不完整）」，并给「继续」（从断处接着写）和「重新生成」（用原问题重新请求）。
5. 摘句核对：模型须只依据所选文件回答，每个结论后附「（文件 N：「原文摘句」）」，找不到依据的写「所选文件中未找到」。摘句逐字照抄，一句以内、不超过 50 字，不跨段落、不跨表格格子；规则写在文件之前，文件之后再重申要点。回答先给结论再分点，可用 Markdown；选了 skill 时按 skill 的格式。确有需要时模型可在末尾另起「文件外补充（未核对）：」一段，这一段不核对、不收录到知识库。回答结束后逐条核对摘句（忽略空白差异，省略号两侧分开核对），找不到的摘句列在回答下方；整条回答没附摘句时也会提示。这些提示一并写进保存的对话。
6. 每条回答可以「复制」「保存为 Word」；「保存对话」把全部问答存成 `资料管家-标题-年月日-时分.md`，整篇「保存为 Word」同样内容存成 .docx。内容从第一问开始，已选文件列在文末的「参考文件」里，编号与回答里的「文件 N」一致；单条回答的 Word 末尾也附上。对话标签先显示第一问的前 12 字，第一轮回答结束后换成模型概括的 10 字以内标题（不带文件和知识库，失败时保留前 12 字）；「清空对话」或改动文件清单后回到「对话 N」。「清空对话」点了直接清空，之后的提问是新对话。
7. 字数上限：页面上一直写着将发送到哪个接口主机、哪个模型、几个文件和字数。文件和对话合计超过「发送字数上限」（默认 10 万字）时先不发送，可以移除文件、调高上限，或「仍然发送」（按比例截断文件部分）。
8. 接口出错时写明原因和下一步：AK 无效或过期（401、403）、接口地址或模型名不对（404）、内容过长、请求太频繁或额度用完（429）。

设置：模型、skill 的设置合在模型与 skill 选项行下方的一个「设置」面板里，分「模型」（发送字数上限、自定义模型接口、配置 OpenCode）和「skill」（新建与安装）两个标签，一次只显示一页；知识库的设置与保存位置在「知识库」卡片头的「设置」里（见下方「知识库」）。选项行里带齿轮图标的「模型设置」「skill 设置」各开对应标签，面板已开且正在该标签时再点收起。打开时面板滚到可见、焦点在当前标签；方向键（← →、Home、End）切换标签；Esc 或「收起」关闭，焦点回到打开它的入口。上次打开的标签记在本浏览器（读不到时为「模型」），刷新后面板收起。每节常驻一句要点与取值范围，其余折在「详细说明」里。切换标签或收起时没保存的输入保留，有未保存改动的标签文字后加圆点（读屏读作「有未保存的改动」），保存或改回原值后消失。没有可用模型时不显示「skill」标签。

支持的格式：

- 纯文本类直接读取：txt、md、csv、tsv、log、json、xml、yaml、ini、conf、sql 和常见代码文件，编码按 UTF-8、GB18030 识别，单个文件最多 20 MB；html、htm 去掉标签后取文字。
- docx、xlsx、xlsm、pptx、eml、pdf 由 `doc2kb_core.py` 转成文字；pdf 需要 `pdftotext`，扫描件取不出文字。
- 旧版 doc、xls、ppt（Office 97 及以后）同样由 `doc2kb_core.py` 取文字和表格；wps、et、dps 分别按 doc、xls、ppt 试读。有密码保护、更早版本或损坏的文件提示先另存为 docx、xlsx 或 pptx。
- 压缩包不读取，提示先解压，可点「打开文件夹」。其他扩展名按纯文本尝试，是二进制文件时提示不支持。
- 每个文件取出的文字开头先写路径、文件名、修改时间，文档里记录了作者时再写作者（和与作者不同的最后修改者），随正文一起发给模型。

提示样式：操作进行中的阶段文字（发送与等待回答、扫描、收录、整理知识库、测试连接、升级与退回、同步、等待选择窗口等）为强调色文字加浅蓝底条，左侧一个小圈在转（纯 CSS，页面卡顿时照转；系统设置了减少动态效果时不转）；结果提示加同色浅底条：完成为绿底，需要留意为黄底，失败为红底，深色模式另配色；普通说明仍为灰字、无底色。

## 索引与缓存

- 只索引添加的文件夹，跳过以 `.` 开头的文件和文件夹、`node_modules`、`__pycache__`，不跟随指向文件夹的链接；读不了的文件夹跳过并在状态里列出。
- 只匹配文件名和路径，不看文件内容。索引缓存在 `~/.cache/ask-local-files/index.json`（权限 600），启动即可搜索，后台只重扫修改时间变了的文件夹。点「刷新」立即检查，「重建索引」全部重扫。

## 模型接口与隐私

- 有 OpenCode 配置（`~/.config/opencode/opencode.jsonc` 或 `opencode.json`）时，列出其中带 `options.baseURL` 和 `options.apiKey` 的服务商下的全部模型；apiKey 可写成 `{env:变量}` 或 `{file:路径}`，服务商的 `headers` 一并带上。
- 配置 OpenCode：「模型设置」里的「配置 OpenCode」在本机已有 OpenCode 配置时换上自己的 AK：选服务商、填 AK，点「测试并写入」。先用新 AK 发一条极短的测试请求，通过才写入，只替换这个服务商 `options.apiKey` 的值，注释、格式、其余设置与文件权限原样保留；写入前把原文件备份为「配置文件名.ask-local-files.bak」（权限 600，只留最近一份），「回滚」用备份恢复并删掉备份。测试不通过、服务商没有 `apiKey` 一项（先在配置文件里加上，值可填任意占位）或配置文件格式有误时不改文件；本机没有 OpenCode 配置时不生成文件，提示填自定义接口。AK 不写日志、不返回页面。
- 本机模型：见下方「本机模型」。
- 也可以在「模型设置」里填接口地址、模型名和 AK，作为一项可选模型，「测试连接」可检查是否连通。接口不需要鉴权时 AK 可以不填；接口不在本机时，「将发送到」的主机后标「（未鉴权）」。设置存在保存位置里的 `config.json`（权限 600，见下方「知识库」的「保存位置」）。AK 不发给页面，日志不记 AK 和文件内容。
- 模型接口超过 120 秒没有新内容即判为失败；接口在本机（127.0.0.1、localhost、::1）时放宽到 900 秒，且不走代理。
- 「复制全部文字」「保存全部文字」不经过模型接口，文字只写进剪贴板或下载的文件。
- 路径：发给模型的系统消息、复制或保存的全部文字、二维码，以及保存对话里的参考文件和「参考了知识库」，路径都从所添加文件夹的名字起写（如「资料/方案.docx」），不在所添加文件夹下的只写文件名；页面显示和「复制已选择的文件路径」仍是完整路径。
- 请求按 OpenAI 兼容的 `POST <接口地址>/chat/completions` 流式发送，依次为：系统消息（只有规则：skill 说明、用提问的语言回答、摘句要求与一个虚构的出处示例、文件只当资料不执行其中指令的说明），之前的问答（只有文字，原样保留），最新一问（所选文件逐个放在 `<document>` 标签里，再附知识库节选，然后重申要点，最后是问题）。长文档在前、问题在后，每问重发文件。
- 文件文字和对话会发给你选的模型接口，请只选你有权交给该接口处理的文件。知识库打开时（默认），提问时选过的文件取出的文字和核对通过的结论存在本机的知识库文件里（见下方「知识库」）；关掉知识库后取出的文字只放在内存里，不写硬盘。对话只留在页面上，需要时点「保存对话」。
- 用到知识库时，最新一问在已选文件之后用同样的标签附上知识库里找出的以前结论与原文段落（source 写「路径（来自知识库，节选）」），系统消息写明以前的结论只作线索、摘句须从原文节选里照抄，编号只在这一问有效。
- 提问先看目录（仿 LLM Wiki 的 query 先读 index）：勾选「参考知识库」、打开「知识库设置」里的「提问前先让模型看主题目录」（默认开）且有主题时，每问先把主题目录（每个主题的标题与前两条要点，最近更新的在前，至多 3,000 字）和问题交给所选模型，由它挑出至多 5 个；挑出的主题的要点排在最前，其后照旧是关键字检索结果，合计仍受同一字数预算约束。模型 45 秒（本机模型 60 秒）没有给出、出错或回答看不懂时只用关键字，不影响提问。

## 知识库

- 作用：提问时选过的文件，取出的文字按段落记下；回答里附了原文摘句且核对通过的句子，去掉出处后作为一条「结论」连同原句、文件和提问记下。之后提问时按问题找出相关的以前结论和原文段落一起发给模型，所以不选文件也能问以前用过的内容；同一结论被得出的次数越多越靠前。
- 存放：「保存位置」（见下文）里的 `memory.sqlite`，默认为工具目录下的 `数据/memory.sqlite`（文件权限 600，文件夹 700），只存取出的文字和原路径，不存原文件，各对话标签共用。库文件打不开或损坏时改名留存，另建新的。
- 知识库卡片：左栏的「知识库」卡片分「文件」「概览」「主题与结论」三个标签。知识库为空时停在「概览」，有内容后回到上次打开的标签（记在本浏览器）。
  - 「文件」：找文件（见「使用方法」）。每个文件第二行带收录标记：「已收录 · N 条结论」（点了在「主题与结论」里只列这份文件的结论）、「待收录」或「未收录：原因」。
  - 「概览」：已收录的文件、结论与主题数；进行中的收录与整理进度（含分批计划与最近几批的记录）；最近整理的主题；可展开的「收录、整理是什么」；「⋯ 更多」里是整理记录（可撤销）、没有收录的文件（按原因分组，各附下一步）、「按新办法重新整理全部……」、「移出不在自动收录范围内的文件……」与「保存为 Markdown」。第一次使用、清空之后、知识库关闭、保存位置不可用时各有对应的说明与按钮。「关系图」在页面内全窗口打开，只读地查看主题、结论与文件之间的关系：点节点展开一层，可拖动、缩放、搜索，一次至多 300 个节点；旁边是同内容的层级列表，键盘与读屏可用，窄屏只显示列表。
  - 「主题与结论」：可搜索（主题、结论、原句或文件路径），每次显示 50 条。主题点开看要点、原句与出处，可移出；结论写原句、文件与得出次数，可「这条不对」。
  - 卡片展开、页面在前台时只刷新看得见的标签：收录或整理进行中至多每 5 秒一次，空闲时每 15 秒一次，保留搜索、展开与滚动位置；10 秒内刚操作过或有对话框开着时跳过这一次。页面上每个按钮都有悬停说明。
- 知识库设置：卡片头带齿轮的「设置」（读屏读作「知识库设置」），点了在标签上方展开，再点或按 Esc 收起。有总开关「打开知识库（收录并在提问时参考）」（默认开；关掉后不收录也不参考，已收录的保留）、「提问前先让模型看主题目录」、「空闲时自动整理」、每批大小、容量上限、保存位置和「清空知识库……」。
- 检索：问题按标点、空格和常见虚词切成关键字，SQLite 带 FTS5 时用全文索引，没有时逐条匹配；按命中的关键字数排序，结论另按被得出的次数和新近程度加分。已选文件里的内容不重复给。
- 与文件一致：取用前检查知识库里的文件，修改时间或大小变了就重新取文字；文件不在了，它的段落、结论和要点一起移出，删光要点的主题一并删除。
- 字数：没选文件时知识库可用发送字数上限扣除 skill 说明与对话后的全部余量；选了文件时至多占这部分余量的三分之一，且只用文件用不完的字数。
- 「这次提问参考知识库」：在 skill 旁，默认勾选。勾选时可以不选文件直接提问。发送按钮旁一行写明这次提问的内容（参考知识库、已选几个文件、发送到哪个模型和字数）。用到知识库的回答上方写明参考了几个主题、几条结论、几段原文，点开后每条都可以点，跳到知识库卡片里的对应位置并高亮，定位栏里的「返回回答」回到原处；已被合并或移出的写明去向。
- 「这条不对」：记下了结论的回答顶部和底部都有，点了立即移出这条回答记下的结论，之后不再收录；「主题与结论」里每条结论旁也有。
- 引导：知识库为空时「问 AI」里显示三步引导：添加文件夹、收录、直接提问（给出按已收录内容拟的示例问题）；「先不建库，直接挑文件提问」可关掉。
- 整理（参考 LLM Wiki 的做法）：模型把知识库维护成一组可积累的主题，每个主题有标题和要点，每条要点带出处文件和原句。新结论、内容变了的文件先排进整理队列，回答时不多调模型。合并重复（次数相加）、以新代旧、删除不再成立的说法都自动进行；模型的回答须是约定的 JSON，要点写入前按文件当前文字核对原句，核对不过或「不对」过的不写入；看不懂的回答这一批不写入。提问时主题要点排在最前（写作「主题：要点」），其次是结论，同一原句只用一次。
- 「现在整理」处理队列并把全部结论体检一遍，显示阶段与第几批，可「停止」（正在处理的那一批不写入）。「空闲时自动整理」（默认勾选）在工具开着、没有回答在生成且 10 分钟没有提问时处理队列，一提问就让路。整理记录列出最近 20 次整理，最近一次可「撤销」，可逐次往回撤销。
- 发送：整理会把结论、原句、相关主题和文件文字发给所选模型，与提问是同一个接口；不想自动发送可取消「空闲时自动整理」。
- 自动收录：「管理文件夹」里每个文件夹旁有「自动收录到知识库」（记在设置里；新添加的文件夹默认勾选）。勾选后其中 Word、Excel、PPT、WPS、PDF、邮件（.docx .pptx .xlsx .xlsm .pdf .eml .doc .xls .ppt .wps .et .dps）、txt 和 Markdown 文件（勾选「忽略 Markdown 文件」时不含 .md）自动收录；网页、代码、表格、配置等其他格式不自动收录，在「没有收录的文件」里归为「格式不自动收录」，手动选用不受影响。
  1. 每次文件夹扫描后以及至多每 10 分钟，在后台把新增或改过的文件取文字按段落收录，马上能被提问参考；只读原文件、不调模型。取不出文字的记下原因，改过后再试。
  2. 收录的文件排进「从文件抽结论」，整理时按文件夹分组、从旧到新，小文件拼成一批（默认每批至多 30,000 字、20 个文件，可在「知识库设置」改，另受发送字数上限限制）交给所选模型抽出带逐字原句的结论；大文件单独分几批，附文件开头一小段和前面已得出的结论。原句核对通过、不是「不对」过、知识库里还没有的才写入，每批抽完紧接着整理进主题，所以每批做完就能被参考。一批失败时重试、对半拆开，单个文件仍失败的跳过并列出、可重试；连不上接口时停下这一轮，下次接着做。一轮结束时自动体检这一轮动过的主题。改过的文件删掉原句已不在的结论后从头重抽。
  3. 抽结论的规则带版本号（当前为 4），规则改了不自动重抽；「按新办法重新整理全部……」确认后删除主题、结论、要点与整理记录，保留收录的原文段落，全部自动收录的文件从头排队。帮助页「原理与提示词」一节公开全部提示词。
  4. 自动收录的文件按从没被选用过算，容量满时先被移出。文件删掉后它的内容一并移出。取消勾选或移除文件夹后，其中的文件不再更新、撤出抽结论的排队，已收录的保留、提问时照旧参考；确认框写明会撤出几个文件。不在勾选的文件夹里或格式不再自动收录的已收录文件，可用「移出不在自动收录范围内的文件……」一并移出，确认框写明数量。
  5. 「立即收录」马上查一遍。退出时收录随之停下，下次启动接着做。
- 清空知识库：页面内的确认框逐项写明会删除的文件数、文字大小、待整理项、结论、要点、主题与整理记录，有回答在生成时写明会被停止。确认后先停下全部任务，再删掉库文件重建空库，并重建文件索引；清空后自动收录暂停，到「立即收录」或下次启动。设置、网址和原文件不受影响。
- 相关主题：整理时模型可为每个主题列出至多 8 个已有的相关主题，随整理撤销；「主题与结论」里显示。
- 保存为 Markdown：存成 `知识库-年月日-时分.zip`，解压后用 Obsidian 打开即可浏览主题与文件之间的链接：`主题/<主题>.md`、`文件/<文件名>.md`、`索引.md`。不含段落全文。
- 容量：知识库里的文字超过「容量上限」（50 到 102,400 MB，默认 1,024 MB）时，先移出最久没被选用或参考的文件及其结论。知识库出错只写日志，提问照常进行。
- 保存位置：知识库 `memory.sqlite`、设置 `config.json`（已添加的文件夹、模型设置等）和网址令牌 `token` 一起存放的文件夹，默认是工具目录下的 `数据/`，升级时整个搬到新版（`upgrade-keep.txt` 里的 `move: 数据`），退回上一版时同样搬回。旧版默认存在家目录（`~/.local/share/ask-local-files/` 与 `~/.config/ask-local-files/`），第一次启动时搬进 `数据/` 并写 `data-dir.txt`；工具目录不可写或搬迁失败时本次仍用家目录，「保存位置」里常驻写明原因，并给「改存到安装目录……」。文件夹索引缓存、自建 skill 目录和日志不随之移动。
  - 更改：「知识库设置」里的「保存位置」写着当前位置；填写或点「选择……」选一个文件夹后点「更改」。新位置三个文件都没有时把当前的移过去（先全部复制，都成功后再删原处），网址不变；新位置已有其中任一个时直接改用那一份，不合并、不覆盖，令牌不同时页面按新网址重新打开。执行前先确认，写明会移动哪几个文件、各多大、从哪里到哪里。有任务进行时不能改。命令行 `--data-dir 目录` 与之等效。
  - 程序目录本身和其中「数据」以外的文件夹升级时不会带到新版，不用作保存位置：填程序目录本身时按其中的「数据」算，填其中别的文件夹时不保存；以前这样放的，启动时搬进「数据」并提示一次。
  - 从上一版取回：升级后知识库是空的、而上一版（工具目录旁的 `.<目录名>.上一版`）里的知识库有内容时，「问 AI」状态行提示一次，「保存位置」里给「从上一版取回……」：只复制，上一版里的文件不动，`数据/` 里现有的同名文件改名为「原名.取回前」留着。
  - 位置记在工具目录的 `data-dir.txt`（一行绝对路径），升级时随保留清单带到新版。记着的位置不可用（如数据盘没有挂载）时不回退家目录：照常启动，页头下方醒目提示；本次不收录也不参考知识库，设置改动不保存，令牌临时生成。挂载或修复后重启，或在「知识库设置」里改到别处。

## 本机模型

- 打开页面、打开设置的「模型」标签或点「重新查找」时，探测本机 `127.0.0.1:8080`（llama-server）与 `127.0.0.1:11434`（Ollama）的 `/v1/models`，每个模型列为「模型名（本机 llama-server）」或「模型名（本机 Ollama）」，请求不带 AK。服务在页面打开后才启动或中途停掉时，点「重新查找」更新列表。
- 发送字数上限按模型上下文折算：llama-server 读 `/props` 的 `n_ctx`，Ollama 读 `/api/ps` 里已加载模型的 `context_length`（尚未加载时按 `OLLAMA_CONTEXT_LENGTH`，没有时 4096）；1 token 按 1 字计，留四分之一给回答，取「上下文 × 0.75」与设置值中较小的。读不到上下文时只按设置值。
- skill 照常可选；llama-server 要加 `--jinja` 启动才接受工具调用。
- 本工具不安装、不启动模型服务，例如 `llama-server -m 模型.gguf --port 8080 --jinja`、`OLLAMA_CONTEXT_LENGTH=16384 ollama serve` 需另行运行。

## skill

skill 是一个文件夹，内有 `SKILL.md`：开头两行 `---` 之间写 `name:` 和 `description:`，其后是给模型的说明；文件夹里还可以放参考文件和 `.py`、`.sh` 脚本（OpenCode 的 skill 格式）。「skill」下拉框列出工具目录 `skills/` 里预装的和 `~/.config/opencode/skills/` 里自建的，默认「不用 skill」。选了 skill 时可以不选文件，也可以不写问题直接发送；每条回答标明用了哪个 skill。

- 「skill」旁的「skill 设置」（设置面板的「skill」标签）把 skill 加进 `~/.config/opencode/skills/`，完成后自动选中：
  - 新建：填名称（小写字母、数字和连字符，不超过 64 个字符）、用途（不超过 1024 字）和说明正文（不超过 5 万字），生成 `SKILL.md`；没填齐或名称不合要求时不写入，写明原因。
  - 安装：点击、拖入或用键盘聚焦后按 Enter 选择 `.zip` 包（最大 5 MB），或填 skill 文件夹的路径（可用时点「选择……」）。根上（或 `.zip` 里唯一的顶层文件夹里）须有含合格 name 与 description 的 `SKILL.md`。包里有绝对路径、`..` 或链接，文件夹里有链接，文件超过 200 个或解压后超过 20 MB 时拒绝。
  - 已有同名自建 skill 时先确认，写明替换哪个文件夹、其中有多少文件；要装的 skill 带 `.py`、`.sh` 脚本时也先确认，写明个数和脚本能做什么。与预装 skill 同名时照装，自建的优先。
  - 先在临时文件夹备齐、校验再替换，中途失败不留半成品，原来的保持不变；装好的文件夹与其中的脚本只给当前用户访问。
  - 回答下方脚本生成的 `.zip` 是 skill 包时多一个「安装」，规则相同；模型不能自己安装。

- skill 正文放在系统消息最前面，计入字数上限。前面的引导语写明：说明里提到的参考文件先读出来再照做，生成、转换、计算时运行脚本，要交给脚本的长内容先用 `write_work_file` 写进工作目录。三个工具的说明写清何时用并给示例；调用失败时交给模型的结果写明原因和怎么改（可读的文件、可运行的脚本、字数上限）。选了文件时照常要求附原文摘句；依据脚本输出或参考文件得出的内容标「（脚本输出）」。
- skill 有参考文件或脚本时，请求按 OpenAI 兼容的函数调用（`tools`）附上工具，模型按需调用：
  - `read_skill_file`：读 skill 文件夹里的文本文件，单个最多 2 万字。
  - `run_script`：运行 skill 文件夹里的 `.py`（用运行本工具的 Python）或 `.sh`（用 bash），参数逐个传入、不经 shell。脚本从环境变量拿到 `ASK_FILES`（已选文件的路径，换行分隔）、`ASK_ROOTS`（已添加的文件夹）、`ASK_OUT`（本次运行的输出目录，写进去的文件可在页面上保存）、`ASK_WORK`（本问的工作目录）和 `ASK_TOOL_DIR`（工具目录，可借用 `doc2kb_core.py`）。
  - `write_work_file`：有脚本的 skill 才提供，把长内容写进 `ASK_WORK` 供脚本读取，单个文件最多 50 万字。工作目录每问新建，回答结束时删除。
  - 路径不能超出 skill 文件夹或工作目录（含经链接跳出）。
- 限制：脚本自动运行，不逐次确认；单次最多 60 秒；每问最多 5 次读取或运行、10 次写入；交给模型的工具结果最多 2 万字。点「停止」同时终止正在运行的脚本。模型接口不支持函数调用时写明原因，可改选只有说明的 skill 或换模型。
- 选用带脚本的 skill 即允许脚本以当前用户身份运行，能读写当前用户能访问的文件；只放来源可信的 skill。脚本输出会发给模型接口。

| `doc-compare` | 文档对比 | 逐行比对两份已选文件，列出新增、删除、修改并归纳实质变化，可另存左右对照的 HTML 报告 | `scripts/compare.py` |
| `office-gen` | 生成 Word 与 Excel | 把整理好的内容生成 docx 或 xlsx，生成的文件可保存 | `scripts/make_docx.py`（Markdown → docx）、`scripts/make_xlsx.py`（JSON → xlsx） |
| `prompt-optimize` | 提示词优化 | 把原始提示词重写为简洁、明确、按编号分层的提示词 | 无 |
| `clarify-needs` | 需求澄清 | 任务描述笼统时先逐个提问摸清需求，问完给出需求摘要，确认后再执行 | 无 |
| `skill-create` | 创建 skill | 和使用者一起起草新 skill，认可后写出 `SKILL.md` 与参考文本，打成 `<名称>.zip`，由使用者点「安装」装上 | `scripts/pack_skill.py`（检查并打包，只收 .md、.txt，不含脚本） |

预装脚本只用 Python 3 标准库，也可以在终端单独运行（按上面的环境变量传入文件），带 `--help` 与 `--log-level`。`summarize-meeting` 原样复制自 [phuryn/pm-skills](https://github.com/phuryn/pm-skills)（MIT License），文件夹里附许可文件与 `UPSTREAM.md`。

预装 skill 按 Anthropic《Skill authoring best practices》写：description 写清做什么、何时用并列出触发词；正文只写模型不知道的；易错的步骤交给脚本、直接运行不读源码；固定格式给虚构示例；关键步骤写明检查与回改，脚本报错写明怎么改。`skill-create` 生成新 skill 时按同样的要求写。`summarize-meeting` 保持原样，其中联网、另存文件的步骤由 skill 引导语改为在回答里直接给出。修改 skill 前后可各跑一次 `python3 tests/skill_eval_run.py --base 接口地址 --model 模型名 [--key AK] [--skill 名称] [--out 报告.md]`（也可用环境变量 `ASK_EVAL_BASE`、`ASK_EVAL_MODEL`、`ASK_EVAL_KEY`）对比报告；每个场景起一份临时的本工具服务，不碰自己的设置与知识库。

## 双击运行与退出

首次双击时，文件管理器可能提示信任或询问运行方式，选允许运行即可；不允许时在「属性」→「权限」里勾选「允许作为程序执行」。放到桌面时，在文件管理器里右键「资料管家」→「发送到桌面快捷方式」，或执行 `ln -s "$PWD/资料管家.desktop" ~/桌面/` 创建链接；不要复制，复制出去的图标找不到程序，双击会提示改用链接。2.12 及以前入口叫「双击运行.desktop」，升级后指向旧名字的桌面链接会失效，需从工具目录重新发送到桌面。

双击时优先用 Chromium 系浏览器（含奇安信、360、统信等国产 Chromium 系浏览器）的应用窗口模式（`--app`）打开，不显示地址栏；命令不在 PATH 里时按这些浏览器的桌面文件找到程序；都找不到时用默认浏览器的普通窗口。

服务只监听 127.0.0.1，默认端口 47821（可用 `--port` 或在保存位置的 `config.json` 里加 `"port": 端口号` 改）；网址带令牌并校验 Host、Origin，令牌首次启动生成，存在保存位置的 `token`（权限 600），之后沿用，所以网址跨重启不变，可收藏或复制到任意浏览器，页脚「复制网址」可复制。`--new-token` 生成新令牌，旧网址作废（本工具运行时不改）。本工具已在同一目录、同一版本运行时，再次启动只打开页面；端口上运行的是别处目录或别的版本的本工具（例如工具目录被移动或替换后旧程序还在）时，先让它退出，端口 10 秒内空出来就由本次接管，它正忙或没能退出时用系统弹窗提示稍后再试；端口被别的程序占用时提示用 `--port` 换端口。关闭全部页面 5 秒后服务退出，点右上角「退出」立即结束，开着的页面一起结束；退出时正在生成的回答、收录与整理一起停下（至多等 15 秒），下次启动接着做。从没有页面连上时 30 分钟后自动退出（`--idle-timeout` 改秒数，0 不自动退出）。日志写在程序目录下的 `ask_local_files.log`（目录不可写时写到 `~/.cache/ask-local-files/`）。

命令行：`python3 ask_local_files.py [--no-browser] [--no-app] [--port N] [--idle-timeout 秒] [--data-dir 目录] [--print-url] [--new-token] [--upgrade zip或目录 [--yes]] [--rollback [--yes]] [--version] [--log-level DEBUG|INFO|WARNING|ERROR]`，`--no-browser` 只打印网址，`--no-app` 用默认浏览器的普通窗口打开，`--port` 指定端口，`--idle-timeout` 指定空闲多少秒后退出（默认 1800，0 不自动退出），`--print-url` 只打印网址不启动，`--new-token` 重新生成令牌并打印新网址，`--data-dir` 更改保存位置（见「知识库」），`--upgrade`、`--rollback` 见「升级」，`--version` 打印版本号；都在标准输出打印一行「网页界面：网址」；日志级别默认 WARNING，可由环境变量 `LOG_LEVEL` 覆盖。

测试：`python3 -m unittest discover -s tests`；装有 Playwright 时 `node --test tests/ui.test.js`。

## 升级

第一次使用时，把发行包解压到自己选定、以后不再挪动的文件夹，再从那里发送到桌面。以后的新版都在这个位置原地替换，路径不变，桌面链接和网址照常可用：

1. 准备新版的 zip（也可以先解压，选解压出的 `ask-local-files` 目录）。
2. 网页界面点右上角「升级」，选择或拖入新版 zip 或解压好的目录。页面列出「当前版本 → 新版本」、两版之间的更新说明、会保留的文件和多出来的文件；所选版本不比当前新时，另外提示是降级还是重装。
3. 看过后点「升级到 vX.Y」。升级期间显示阶段文字、按钮不可用；有回答正在生成（含 skill 脚本运行）或手动整理知识库时先等它结束，等待时写明在等什么，可点「取消等待」，取消后工具目录不改动；自动收录与空闲时自动整理随之停下，新版启动后接着做。完成后服务以同一端口与令牌用新版重新启动，页面自动重新连上。

命令行同样可以升级：`python3 ask_local_files.py --upgrade 新版.zip`（检查后在终端确认，加 `--yes` 不询问）；本工具须已退出。

- 会保留的文件：`upgrade-keep.txt` 列出的 `data-dir.txt`（改过保存位置时才有）和 `ask_local_files.log`（服务日志）。知识库、设置与令牌在保存位置，不在工具目录里，升级不碰它们。
- 多出来的文件：工具目录里既不在保留清单、也不属于新版的文件，升级前列出来，不删除，随旧目录留在上一版里。
- 上一版：旧目录改名为同一文件夹里的隐藏目录 `.ask-local-files.上一版`，只保留一份。页面「退回上一版」或 `python3 ask_local_files.py --rollback` 把它与当前版本对调，再执行一次即换回。
- 以下情况不升级，并写明原因，工具目录保持不变：所选的不是本工具的发行包（顶层目录名不是 `ask-local-files`）、读不出版本、缺少主程序或双击入口、包里有 `..`、绝对路径、符号链接或设备文件、解压后超过 200 MB 或 5000 个条目、工具目录的上一级文件夹不可写。升级中途出错时恢复原样。
- 页面上传的 zip 只写到系统临时目录，用完删除；选目录时由页面打包成 zip 再上传。
- 从还没有升级功能的 2.14 及以前版本升级：先把新版解压到别处，运行一次 `python3 <解压出的目录>/tool_upgrade.py --tool-dir <原工具目录> --upgrade 新版.zip`，之后就可以用上面的方式升级。
