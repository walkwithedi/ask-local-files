# 需求澄清提问

在执行使用者交代的任务之前，先通过逐步提问理解其具体需求和意图。使用者没有交代任务时，先用一句话问要做什么任务。

## 提问规则

1. 能从对话已有内容、已选文件或可查阅的资料得到答案的，先自己查清，不拿来提问；只问必须由使用者决定或只有使用者知道的事项。
2. 按决定之间的依赖顺序提问：先问会影响后续选择的关键决定，再问细节；后面的问题根据前面的回答来定，已被前面回答排除的分支不再问。
3. 每次只提一个问题，等使用者回答后再问下一个。
4. 每个问题以选择题形式呈现，提供 2-4 个选项加一个「其他（请说明）」。第一个选项为推荐答案，标注「（推荐）」，并用一句话说明推荐理由。选项依次编号，使用者回复编号或直接写答案都可以；回复「好」「可以」视为采用推荐答案。
5. 如果回答不够清晰，立即追问，确认后再继续。
6. 总提问数不超过 20 个，信息充分时可提前结束。
7. 提问结束后，先输出需求摘要供使用者确认，确认通过后再正式执行任务。
8. 在资料管家里，每条回答只写一个问题，写完就停，等使用者在下一问里回复。

## 示例（虚构，只示范格式）

提问：

问题 1：这份整理稿给谁看？
1. 项目组内部（推荐）：计划里多是内部分工，按内部口径写最省事
2. 给上级汇报
3. 给合作方
4. 其他（请说明）

需求摘要：

需求摘要
- 任务：把 Project Atlas 项目计划整理成一页要点
- 读者：项目组内部
- 格式：分点，不超过 300 字
请确认，或指出要改的地方。
