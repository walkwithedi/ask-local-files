# 创建 skill

帮使用者写一个新的 skill。skill 是一个文件夹：根上的 `SKILL.md` 开头两行 `---` 之间写 `name:` 和 `description:`，其后是给模型的说明正文；需要时另放参考文本。你只负责写和打包，安装由使用者在页面上点「安装」完成，你不能也不要试图自己安装。

## 步骤

1. 问清要求：这个 skill 做什么、什么时候用、输入是什么、输出成什么格式。要求已经清楚的不再问；一次最多问 3 个问题。
2. 给出草稿：在回答里写出名称、用途和说明正文的完整草稿，请使用者确认或提出修改。使用者没有明确认可之前，不写文件、不打包。
3. 写文件：使用者认可后，用 write_work_file 把 `SKILL.md` 写到 `skill/SKILL.md`；需要参考文本时写到 `skill/` 下，如 `skill/references/术语表.md`。
4. 打包：用 run_script 运行 `scripts/pack_skill.py skill`。脚本输出「打包失败」时，按原因改正后重新写入、重新打包。
5. 回答：说明打出了哪个包、包含哪些文件，提醒使用者点回答上方运行记录下的「安装 <名称>.zip」，安装后会自动选中这个 skill；也可以先点「保存」留一份。

## 写法要求

- 名称：小写字母、数字和连字符，不超过 64 个字符，如 `weekly-report`；与预装 skill 同名时，自建的会优先，除非使用者要求，不要用预装 skill 的名称。
- 用途（description）：一两句话写清做什么、使用者说什么时用，不超过 1024 字，写在一行里。
- 正文：写给模型看，按「做什么、步骤、输出格式、注意」组织，规则写成可直接执行的指令；不超过 5 万字。
- 只写说明和参考文本（.md、.txt），不写脚本：打包脚本会拒绝其他类型的文件。使用者需要脚本时，说明脚本要由使用者自己审阅后放进 skill 文件夹。
- 不写真实的人名、单位、内部地址和业务数据；举例时用「张三」「某某公司」这类占位写法。

## 注意

- 写入与运行各有次数上限：每个问题最多写入 10 次、运行 5 次；草稿确认放在前面的回答里，确认后的那一问再写入和打包。
- 包在临时目录里，服务退出时删除；需要留存时请使用者先保存或安装。
