# ask-local-files: ask an LLM about your local files

[中文](README.zh-CN.md)

Ask a large language model about your own files on a computer where you cannot install anything. All it needs is Python 3 and a browser. It works with any OpenAI-compatible API, and every answer quotes the files and gets those quotes checked.

- No install: the Python 3 standard library only. Double-click the desktop entry or run one command, then use it in the browser. The page loads nothing from the network.
- You pick the files and they are sent whole: find files by name in the folders you added, pick a few and send them with your question. There is no vector store and no chunk retrieval.
- Quote checking: the model must back each statement with a quote from the files. When the answer ends, each quote is looked up in the file text, and quotes that cannot be found are flagged, so invented support shows.
- Knowledge base: files picked for a question and conclusions whose quotes passed the check are kept on this computer and consulted for later questions, so you can ask about earlier material without picking files again. It can be turned off, inspected and cleared.
- Folders included automatically: tick 自动收录到知识库 ("include in the knowledge base") on an added folder and its files are read into the knowledge base in the background; the model then extracts conclusions with checked quotes and files them into linked topics, which can be saved as Markdown for Obsidian.
- Also useful without a model: find and preview files, then copy or save their extracted text, quoting rules included, to ask an assistant elsewhere.
- Only the endpoint you configure is contacted. That can be an in-house model gateway, a self-hosted vLLM or a public cloud API; llama-server or Ollama running on this computer is found automatically. If you already use OpenCode, its model configuration is read automatically.

The page is in Chinese.

## Requirements

- Python 3.8 or later, and a browser with `fetch` and streaming responses (a recent Firefox or Chromium). Double-clicking works on Linux desktops; elsewhere, start it from a terminal.
- Optional: `pdftotext` (poppler-utils). Without it, PDFs cannot be read; other formats still work.
- An OpenAI-compatible endpoint (base URL, model name and, when it needs one, an API key), or llama-server or Ollama running on this computer. No other network access and no packages to install.

## Use

Download `ask-local-files-v<version>.zip` from Releases and unpack it. Unpack it into a folder you will keep it in, because later versions replace it in place there (see [Upgrade](#upgrade)). Double-click `资料管家.desktop`, or run `python3 ask_local_files.py`.

On a wide screen the page fills the browser window: on the left the 知识库 ("knowledge base") card, with the tabs 文件, 概览 and 主题与结论 (see [Knowledge base](#knowledge-base)), and 已选; on the right the conversation. 知识库, 已选 and 问 AI fold to one line when you click their title, with a short summary beside it; the folding is remembered in the browser, and when one column is fully folded the other takes the width. On a narrow screen 知识库 folds itself once a conversation starts. A 跳到提问框 ("skip to the question box") link appears first in the header when it gets keyboard focus, and Ctrl+L focuses the question box at any time. ＋ 新对话 ("new conversation") opens another conversation tab in the same window, up to 8, each with its own files; its × closes it at once, without asking, stopping an answer in progress and discarding unsaved turns.

1. Add folders under 管理文件夹 (manage folders). On first use the knowledge base card opens at 概览; 添加文件夹 ("add folders") there, or step 1 of the guide in 问 AI, switches to the 文件 tab and opens it. 管理文件夹 is a dialog that fills most of the window (all of it on a narrow screen); the rest of the page cannot be used while it is open. 完成 ("done") or Esc closes it, focus returns to the 管理文件夹 button and the file list refreshes. With no folders yet, the 文件 tab does not open it by itself; the list offers 添加文件夹 instead. Give an absolute path, one starting with `~/`, or a local `file:///` address copied from a file manager; or press 选择…… ("choose") to pick one in the system's folder dialog (zenity, kdialog or tkinter, whichever is found). While the dialog is open the status shows how many seconds it has been waiting, adds after 10 seconds that the dialog may be behind the browser, and a 取消 ("cancel") button next to it closes the dialog; there is no automatic timeout. Indexing runs in the background, and you can search while it runs.
2. Find files in the 文件 tab of the knowledge base card, one view: the folder path on top (全部 for all added folders), then the search box (× clears it) and the extension box. The page reopens in the folder used last (remembered in the browser; 全部 when it is gone). 选项 ▸ ("options") next to 刷新 and 管理文件夹 is closed by default (remembered in the browser; it reads 选项（N 项已改） when N options differ from their defaults) and holds 排序 and the tick boxes 按文件名去重, 正则表达式 and 忽略 Markdown 文件. 排序 ("sort") offers newest first (the default), oldest first (by modification time), name A→Z or name Z→A (ignoring case), remembered in the browser; lists are sorted before the display limit is applied.
   - With both boxes empty the view lists the current folder: subfolders first, by name, with the number of files they hold, then the files of this folder and all its subfolders, the same as an empty search here: in the chosen order, up to 300, each with its folder (click it to go there). Files with the same modification time are ordered by path. Inside a folder, 全部加入 ("add all") adds the readable files of that folder and all its subfolders.
   - Typing in either box searches the current folder and all its subfolders (everything at 全部). Several words must all match the path below that folder, and the extension box filters by type. With 正则表达式 ("regular expression") ticked, the whole box is one Python regular expression, case-insensitive. Results follow the chosen order, up to 300. Moving to another folder through the path or a result's folder keeps the keywords and searches there.
   - Formats the tool cannot read say why. Archives and other unreadable files offer 打开文件夹 ("open folder"); every other file has a folder icon button ("在文件夹中显示", show in folder). Both open the containing folder in the file manager with the file selected: `org.freedesktop.FileManager1.ShowItems` through `gdbus` or `dbus-send` first, then `peony --show-items`, `nautilus --select` or `caja --select`, and finally `xdg-open` or `gio open`, which opens the folder without selecting. When nothing works, the path is shown with a copy button.
   - 从列表移除 ("remove from list") hides one entry from the current list only; it comes back after a new search, another folder or a refresh.
   - 忽略 Markdown 文件 ("ignore Markdown files", on by default, saved in the settings) leaves .md and .markdown files out of search and browse, including file counts, 全部加入 and 加入前 N 个; folders holding only such files are not listed. An explicit md or markdown in the extension box still lists them. Picked files stay; the index is unchanged.
   - 按文件名去重 ("one per file name", on by default) lists only the newest of files with the same name and notes how many others there are; they can be expanded and added one by one. Names match ignoring case, with the same extension, after removing one copy marker such as " (1)", "（2）", " - 副本" or " copy". This changes the list and 全部加入 only, never the index or the files.
3. Pick up to 50 files. When the list (after de-duplication and removals) holds fewer than 50, 全部加入 adds every readable file not yet picked. With more than 10, 30 or 50 files to add, 加入前 10 个, 加入前 30 个 and 加入前 50 个 ("add the first 10 / 30 / 50") take them in the chosen order (in a folder, subfolders included); they are disabled when fewer places are left. You can preview the extracted text and remove files. 复制已选择的文件路径 ("copy the picked file paths") copies their full paths, one per line, to paste into an agent such as OpenCode that works on the files directly; if copying fails, the paths are shown to copy by hand. Files are numbered to match the "文件 N" ("file N") labels sent to the model. Changing the files after the conversation started begins a new conversation.
   复制全部文字 ("copy all text") and 保存全部文字 ("save all text", to `资料管家-文字-<date>-<time>.md`) take the same text the model would get, without the question: the answer-language and quoting rules, then each file's full text in a `<document index="N"><source>path</source><document_content>…</document_content></document>` block, then the rules repeated; no skill instructions and no character limit. Paste it into any assistant and add your question. Files without text are skipped and counted. Both work with or without a model.
4. Without any usable model (no OpenCode model, no local model and no complete custom endpoint), 问 AI shrinks to one line with 模型设置 ("model settings", see below) and moves below the knowledge base card on the left, while 已选 takes the right column; filling in a custom endpoint brings the conversation back.
   Choose a model and, if you like, a skill (see [Skills](#skills)). Write the task (summarise, rewrite, compare) and send it with Enter or Ctrl+Enter; Shift+Enter starts a new line. The answer streams in and is laid out as common Markdown, and follow-up questions keep the same files and the earlier turns. An answer cut short by 停止 ("stop") or an error offers 继续 ("continue", picks up where it stopped) and 重新生成 ("regenerate").
5. Quote checking: each statement must end with a quote from file N, or say that the files do not contain the answer. Quotes are copied word for word, one sentence or less and at most 50 characters, never across paragraphs or table cells. The rules come before the files and are repeated after them. Answers lead with the conclusion, then points (Markdown allowed); with a skill, its own format applies. When needed, the model may end with a 文件外补充（未核对）："outside the files (unchecked)" section; it is not quote-checked and not kept in memory. When the answer ends, each quote is checked against the file text, ignoring whitespace and treating an ellipsis as a gap. Missing quotes, and answers with no quotes at all, are flagged below the answer. The flags are also written into a saved conversation.
6. Copy an answer or save it as Word, save the whole conversation as Markdown or Word, or clear the conversation to start a new one. Saved conversations start at the first question and list the files at the end under 参考文件 ("reference files"), numbered as in the answers; a single answer saved as Word ends with them too. File names are `资料管家-<title>-<date>-<time>`. Conversation tabs show the first 12 characters of the first question, then a title of up to 10 characters that the model writes after the first answer (without files or knowledge base; kept as is if that fails); clearing the conversation or changing the files returns the tab to 对话 N.
7. The page always shows which host and model the request goes to, how many files are included and how many characters. Above the character limit (100,000 by default), nothing is sent until you remove files, raise the limit, or choose 仍然发送 ("send anyway"), which truncates the files proportionally.
8. Endpoint errors say what went wrong and what to do next: 401 or 403 for the key, 404 for the URL or model, a context that is too long, and 429 for rate limits or quota.

Settings: one 设置 ("settings") panel below the model and skill row, with two tabs, 模型 ("model": character limit, custom endpoint, configure OpenCode) and skill (create and install), one page at a time; the knowledge base settings and the storage location are under 设置 in the knowledge base card header (see [Knowledge base](#knowledge-base)). The two entries in that row, 模型设置 and skill 设置, each with a gear icon, open the panel at their tab, and close it when it is already open at that tab. Opening scrolls the panel into view and moves focus to the tab; arrow keys (and Home, End) switch tabs; Esc or 收起 ("close") closes it and returns focus to the entry that opened it. The last tab is remembered in the browser (the 模型 tab when that cannot be read), and the panel is closed after a reload. Each section shows one line with the key point and allowed range; the rest folds behind 详细说明 ("details"). Unsaved input survives switching tabs and closing; a tab with unsaved changes shows a dot (read out as 有未保存的改动, "unsaved changes") until it is saved or set back. Without a usable model, the skill tab is not shown.

Formats: plain text and code files are read as UTF-8 or GB18030, up to 20 MB each. HTML is read with its tags removed. docx, xlsx, xlsm, pptx, eml and pdf are read through `doc2kb_core.py`; pdf needs `pdftotext`, and scanned PDFs have no text. Old binary doc, xls and ppt (Office 97 and later) are read through `doc2kb_core.py` too, and wps, et and dps are tried as doc, xls and ppt; password-protected, older or damaged files ask to be saved as docx, xlsx or pptx first. Archives are not read; unpack them first. The extracted text of each file starts with its path, name and modification time, and its author (and a different last editor) when the document records one; these lines go to the model with the text.

Status messages: steps in progress (sending and waiting for an answer, scanning, inclusion, knowledge base organising, connection tests, upgrade and rollback, sync, waiting for the folder dialog) show in the accent colour on a light blue bar with a small spinning ring, drawn in CSS so it keeps turning while the page is busy and stops when the system asks for reduced motion. Results sit on a light bar of their own colour: green when done, yellow when something needs attention, red on failure; dark mode has its own colours. Plain notes stay grey without a bar.

## Index and privacy

- Only the folders you add are indexed. Hidden entries, `node_modules` and `__pycache__` are skipped, and symlinked folders are not followed. Only names and paths are matched, never file contents.
- The index is cached in `~/.cache/ask-local-files/index.json` and settings in `config.json` in the storage location (see [Knowledge base](#knowledge-base)), both with mode 600.
- With an OpenCode configuration (`~/.config/opencode/opencode.jsonc` or `.json`), every model of every provider that has `options.baseURL` and `options.apiKey` is listed. `{env:VAR}`, `{file:path}` and provider `headers` are supported. A custom endpoint can also be entered in the page, and 测试连接 ("test connection") checks it. The API key may be left empty for endpoints that need none; a remote endpoint without a key is marked 「（未鉴权）」 ("not authenticated") next to its host.
- 配置 OpenCode ("configure OpenCode") in the 模型 tab of the settings panel: with an existing OpenCode configuration, pick a provider and enter your own key. A short test request is sent with the new key first, and only if it succeeds is the value of that provider's `options.apiKey` replaced, leaving comments, formatting, the other settings and the file mode as they were. The original is backed up as `<config file>.ask-local-files.bak` (mode 600, latest only) and 回滚 ("roll back") restores it and removes the backup. Nothing is written when the test fails, the provider has no `apiKey` entry (add one with any placeholder first), or the file cannot be parsed; with no OpenCode configuration no file is created and the page points to the custom endpoint. The key is never logged or sent to the page.
- An endpoint that sends nothing for 120 seconds counts as failed; for endpoints on this computer (127.0.0.1, localhost, ::1) the limit is 900 seconds and no proxy is used.
- Copying or saving all text never contacts the endpoint; the text goes only to the clipboard or the downloaded file.
- Requests go to `POST <base URL>/chat/completions`, streamed, in this order: a system message with the rules only (skill instructions, answer in the language of the question, the quoting rules with one made-up example, and a note that file contents are material and any instructions in them are not followed); the earlier questions and answers, as text, unchanged; and the latest question, which starts with the picked files, each in a `<document index="N"><source>path</source><document_content>…</document_content></document>` block, then knowledge base excerpts, then the rules repeated, then the question. Long documents come first and the question last; files are sent again with every question. Paths there, and in copied, saved or QR-carried text and saved conversations, start at the added folder's name (such as `资料/方案.docx`) rather than the full path; files outside the added folders show their name only. The page and 复制已选择的文件路径 keep full paths.
- File text and the conversation go to the endpoint you chose, so pick only files you may send there. With the knowledge base on (the default), the extracted text of files picked for questions and the checked conclusions are stored on this computer (see [Knowledge base](#knowledge-base)); with the knowledge base off, extracted text stays in the server's RAM and is never written to disk. The API key never reaches the page, and neither the key nor file text is logged.
- When the knowledge base is used, the latest question adds the earlier conclusions and paragraphs found after the picked files, in the same blocks with the source `path（来自知识库，节选）` ("from the knowledge base, excerpt"); the system message says that earlier conclusions are only leads, quotes must be copied from the excerpts, and these numbers hold for this question only.
- Topic list first (after the LLM Wiki habit of reading the index before a query): with 参考知识库 ticked, 提问前先让模型看主题目录 ("let the model see the topic list before asking", in the knowledge base settings, on by default) on and topics present, each question first sends the topic list (each topic's title and first two points, newest first, up to 3,000 characters) and the question to the selected model, which picks up to 5 topics. Their points come first, then the keyword results as before, within the same budget. If the model gives nothing within 45 seconds (60 for a local model), fails, or replies in a form that cannot be read, only keywords are used and the question goes on.

## Knowledge base

- What it keeps: the extracted text of files picked for a question, by paragraph, and every sentence of an answer whose quote passed the check, stored without its source as a conclusion together with the quoted sentence, the file and the question. Later questions retrieve related conclusions and paragraphs and send them along, so you can ask without picking files. A conclusion reached more often ranks higher.
- Where: `memory.sqlite` in the storage location (below), by default `数据/memory.sqlite` in the tool folder (file mode 600, folder 700). Only extracted text and original paths are kept, never the files. All conversation tabs share it. A database that cannot be opened is renamed and a new one started.
- The 知识库 ("knowledge base") card in the left column has three tabs: 文件 ("files"), 概览 ("overview") and 主题与结论 ("topics and conclusions"). It opens at 概览 while the knowledge base is empty, and at the last tab used (remembered in the browser) once it has content.
  - 文件: finding files (see [Use](#use)). Each file's second line carries an inclusion mark: 已收录 · N 条结论 ("included, N conclusions"; click it to list that file's conclusions), 待收录 ("waiting") or 未收录：reason ("not included").
  - 概览: the number of files, conclusions and topics; inclusion and organising in progress, with the batch plan and the latest batches; recently organised topics; an expandable 收录、整理是什么 ("what inclusion and organising are"). Under ⋯ 更多 ("more"): the organising history (with undo), files left out (grouped by reason, each with what to do next), 按新办法重新整理全部…… ("reorganise everything the new way"), 移出不在自动收录范围内的文件…… ("remove files outside the automatic inclusion scope") and 保存为 Markdown. First use, after clearing, with the knowledge base off and with an unusable storage location each get their own note and button. 关系图 ("graph") opens a full-window, read-only view of how topics, conclusions and files relate: click a node to expand one level, drag, zoom and search, up to 300 nodes at a time; a tree list with the same content works with the keyboard and screen readers, and narrow screens show only the list.
  - 主题与结论: searchable (topics, conclusions, quotes or file paths), 50 entries at a time. A topic opens to its points with quotes and sources and can be removed; a conclusion shows its quote, file and count and has 这条不对 ("this is wrong").
  - While the card is open and the page is in front, only the visible tab refreshes: at most every 5 seconds while inclusion or organising runs, every 15 seconds otherwise, keeping the search, expanded entries and scroll position; a refresh is skipped within 10 seconds of your last click or key press there, or while a dialog is open. Every button on the page has a tooltip.
- Knowledge base settings: 设置 with a gear icon in the card header (read out as 知识库设置) opens above the tabs; click it again or press Esc to close. It holds the switch 打开知识库（收录并在提问时参考） ("knowledge base on: include, and consult when asking"; on by default; off stops inclusion and consulting and keeps what is stored), 提问前先让模型看主题目录 ("let the model see the topic list before asking"), 空闲时自动整理 ("organise when idle"), the batch size, the capacity limit, the storage location and 清空知识库…… ("clear knowledge base").
- Retrieval: the question is split into keywords at punctuation, spaces and common function words; SQLite FTS5 is used when available, a plain scan otherwise. Results rank by matched keywords, conclusions also by how often and how recently they were reached. Content of the picked files is not repeated.
- Kept in step with the files: before use, a file whose modification time or size changed is read again; a file that no longer exists is removed with its paragraphs, conclusions and points, and topics left without points go too.
- Size: without picked files, the knowledge base may use what is left of the character limit after the skill and the conversation; with picked files, at most a third of that, and only what the files leave unused.
- 这次提问参考知识库 ("use the knowledge base for this question"), next to the skill menu, is ticked by default; then you may ask without files. A line next to 发送 says what this question sends: the knowledge base, how many picked files, which model, and the characters. An answer that used the knowledge base says how many topics, conclusions and paragraphs it drew on; each can be clicked to jump to it in the knowledge base card, highlighted, with 返回回答 ("back to the answer") to return; entries merged or removed since say where they went.
- 这条不对 at the top and bottom of an answer that added conclusions removes them at once and keeps them from being added again; each conclusion under 主题与结论 has it too.
- Guide: while the knowledge base is empty, 问 AI shows three steps: add folders, inclusion, ask (with example questions drawn from what has been included). 先不建库，直接挑文件提问 ("skip the knowledge base, pick files and ask") hides it.
- Organising (after the LLM Wiki pattern): the model keeps the knowledge base as topics that grow over time, each with a title and points, each point with its file and quote. New conclusions and changed files wait in a queue, so answers do not slow down. Merging duplicates (counts add up), replacing superseded statements and deleting ones that no longer hold happen without asking. Replies must be the agreed JSON; every point is checked against the file's current text before it is written, and ones that fail or were marked wrong are not; a batch whose reply cannot be read is not written. Questions draw on topic points first, written as "topic: point", then conclusions, each quote once.
- 现在整理 ("organise now") works through the queue and checks every conclusion, showing the stage and batch; 停止 ends it without writing the batch in progress. 空闲时自动整理 (on by default) works through the queue when the tool is open, no answer is being written and no question has come for 10 minutes, and gives way as soon as a question comes. The history lists the last 20 runs; 撤销 ("undo") on the newest one restores the state before it, one run at a time.
- Organising sends conclusions, quotes, related topics and file text to the selected model, the same endpoint as questions; untick 空闲时自动整理 to organise only on demand.
- Including folders automatically: each added folder in 管理文件夹 has 自动收录到知识库 ("include in the knowledge base"), saved in the settings and ticked for newly added folders. For ticked folders, Word, Excel, PowerPoint, WPS, PDF and e-mail files (.docx .pptx .xlsx .xlsm .pdf .eml .doc .xls .ppt .wps .et .dps), txt and Markdown (not .md while 忽略 Markdown 文件 is ticked) are included. Web pages, code, tables, configuration and other formats (such as .html .css .js .py .csv .json .xml) are not; they are listed as 格式不自动收录 ("format not included automatically") and can still be picked by hand.
  1. After each folder scan and at most every 10 minutes, new and changed files are read in the background and stored by paragraph, ready for questions at once. The files are only read and no model is called. Files that give no text are listed with the reason and retried once they change.
  2. Included files are queued for conclusion extraction. Organising groups them by folder, oldest first, and joins small files into one batch (by default at most 30,000 characters and 20 files, set in the knowledge base settings, also within the character limit) for the selected model to extract conclusions with word-for-word quotes; large files go in several batches with the start of the file and the conclusions so far. A conclusion is stored only when its quote is found in the current text, was not marked wrong and is not already there, and each batch is filed into topics right away, so it is usable as soon as it is done. A failing batch is retried and then split in half; a single file that still fails is skipped and listed, and can be retried; an unreachable endpoint ends the round until next time. At the end of a round the topics it touched are checked. A changed file has the conclusions whose quote is gone removed and is extracted again from the start.
  3. Extraction rules have a version (now 4); a rule change does not trigger re-extraction by itself. 按新办法重新整理全部…… asks first, then deletes topics, conclusions, points and history, keeps the included paragraphs and queues every automatically included file from the start. The help page's 原理与提示词 ("principles and prompts") section prints every prompt in full.
  4. Included files count as never picked and are removed first when the knowledge base is full. A deleted file is removed with its content. Unticking or removing a folder stops updating its files and takes them out of the extraction queue; what is stored stays and is still consulted, and the confirmation says how many files leave the queue. Stored files outside the ticked folders or in formats no longer included can be removed together with 移出不在自动收录范围内的文件……, which says how many first.
  5. 立即收录 ("include now") checks at once. Inclusion stops on quit and resumes on the next start.
- 清空知识库 opens a dialog in the page listing what will be deleted (files and text size, queued items, conclusions, points, topics and the history) and that an answer being written will be stopped. It then stops every task, deletes the database file, starts an empty one and rebuilds the file index; automatic inclusion pauses until 立即收录 or the next start. Settings, the address and the files are untouched.
- Related topics: organising may list up to 8 existing related topics for each topic, undone with the run; 主题与结论 shows them.
- 保存为 Markdown saves `知识库-<date>-<time>.zip`. Unpacked and opened as an Obsidian vault, it links topics and files: `主题/<topic>.md`, `文件/<file name>.md` and `索引.md`. Paragraph text is not included.
- Capacity: above the limit (容量上限, 50 to 102,400 MB, default 1,024 MB) the files least recently picked or consulted are removed first. Knowledge base errors are logged and questions go on without it.
- Storage location (保存位置): knowledge base (`memory.sqlite`), settings (`config.json`: added folders, model settings and so on) and the address token (`token`) are kept together, by default in `数据/` in the tool folder, which moves to the new version on upgrade (`move: 数据` in `upgrade-keep.txt`) and back on rollback. Earlier versions kept them in the home folder (`~/.local/share/ask-local-files/` and `~/.config/ask-local-files/`); the first start moves them into `数据/` and writes `data-dir.txt`. When the tool folder is not writable or the move fails, the home folder is used for this run, the 保存位置 section says why, and 改存到安装目录…… ("store in the tool folder") is offered. The folder index cache, your own skills folder and the log stay where they are.
  - Changing it: 保存位置 in the knowledge base settings shows the current location; type a folder or pick one with 选择…… and press 更改 ("change"). If the new folder holds none of the three files, the current ones are moved there (all copied first, the originals removed only once every copy succeeded) and the address stays the same. If it holds any of them, those are used as they are, nothing is merged or overwritten, and when the token differs the page reopens at the new address. A confirmation lists the files with their sizes and both places first. Changing is refused while a task is running. `--data-dir DIR` on the command line does the same.
  - The tool folder itself and folders inside it other than `数据/` are not carried to a new version, so they are not used as the location: the tool folder itself counts as its `数据/`, any other folder inside it is refused, and a location recorded there earlier is moved into `数据/` on start, with a notice.
  - Restore from the previous version: when the knowledge base is empty after an upgrade and the previous version (`.<folder name>.上一版` next to the tool folder) holds one with content, 问 AI notes it once and 保存位置 offers 从上一版取回…… ("restore from the previous version"). It only copies: the previous version is untouched, and files of the same name in `数据/` are renamed to `<name>.取回前` and kept.
  - The location is recorded in `data-dir.txt` in the tool folder (one absolute path) and carried to new versions on upgrade. When the recorded folder is unusable (for example a data disk that is not mounted), the tool does not fall back to the home folder: it starts with a prominent notice, neither adds to nor consults the knowledge base, keeps setting changes in RAM only and uses a temporary token. Mount or fix the folder and restart, or change the location in the knowledge base settings.

## Local models

- When the page opens, when the 模型 tab of the settings panel opens or when 重新查找 ("look again") is pressed, `/v1/models` is queried on `127.0.0.1:8080` (llama-server) and `127.0.0.1:11434` (Ollama). Each model is listed as 「name（本机 llama-server）」 or 「name（本机 Ollama）」, and requests carry no key.
- The character limit follows the model's context: `n_ctx` from llama-server's `/props`, or the loaded model's `context_length` from Ollama's `/api/ps` (`OLLAMA_CONTEXT_LENGTH`, else 4096, before it is loaded). One token counts as one character and a quarter is left for the answer, so the limit is the smaller of context × 0.75 and the configured limit.
- Skills work as usual; llama-server needs `--jinja` to accept tool calls.
- The tool neither installs nor starts a model server; run, for example, `llama-server -m model.gguf --port 8080 --jinja` or `OLLAMA_CONTEXT_LENGTH=16384 ollama serve` yourself.

## Skills

A skill is a folder holding `SKILL.md`: `name:` and `description:` between two `---` lines at the top, then instructions for the model. The folder may also hold reference files and `.py` or `.sh` scripts (the OpenCode skill format). The skill menu lists the bundled skills in `skills/` and your own in `~/.config/opencode/skills/`; the default is no skill. With a skill chosen you may send without files or without a question, and every answer names the skill it used.

- skill 设置 ("skill settings") next to the skill menu adds skills to `~/.config/opencode/skills/` and selects the new one:
  - Create: a name (lowercase letters, digits and hyphens, up to 64 characters), a description (up to 1,024 characters) and the instructions (up to 50,000 characters) become `SKILL.md`. Missing fields or a bad name are reported and nothing is written.
  - Install: a `.zip` file, clicked, dropped or opened with Enter on the focused drop area (up to 5 MB), or a folder path (选择…… opens a folder picker where available). `SKILL.md` must sit at the top, or in the zip's single top folder, with a valid name and description. Absolute paths, `..` or links in the package, links in the folder, more than 200 files or more than 20 MB unpacked are refused.
  - Replacing a skill of your own with the same name asks first, naming the folder and how many files it holds; so does installing a skill with `.py` or `.sh` scripts, saying how many and what scripts may do. A bundled skill with the same name stays, and yours takes precedence.
  - Files are staged in a temporary folder and checked before they replace anything, so a failure leaves no partial skill and keeps the old one. The installed folder and its scripts are accessible to the current user only.
  - A `.zip` written by a script under an answer that holds a skill gets an 安装 ("install") button with the same rules; the model cannot install anything itself.

- The skill's instructions open the system message and count towards the character limit. The introduction before them tells the model to read reference files before following them, to run scripts for generating, converting or computing, and to write long input for scripts with `write_work_file` first. Each tool description says when to use it and gives an example; a failed call returns the reason and what to change (the files that can be read, the scripts that can run, the size limits). With files picked, quotes are still required; statements taken from script output or reference files are marked 「（脚本输出）」 ("script output").
- When the skill has reference files or scripts, the request carries OpenAI-compatible function tools (`tools`) that the model calls as needed:
  - `read_skill_file` reads a text file in the skill folder, up to 20,000 characters.
  - `run_script` runs a `.py` file (with the Python running the tool) or a `.sh` file (with bash) in the skill folder, arguments passed one by one, no shell. The script gets `ASK_FILES` (paths of the picked files, one per line), `ASK_ROOTS` (the added folders), `ASK_OUT` (an empty output folder; files written there can be saved from the page), `ASK_WORK` (this question's work folder) and `ASK_TOOL_DIR` (the tool folder, so it can use `doc2kb_core.py`).
  - `write_work_file`, offered only to skills with scripts, writes long content into `ASK_WORK` for a script to read, up to 500,000 characters per file. The work folder is created for each question and removed when the answer ends.
  - Paths cannot leave the skill folder or the work folder, through links neither.
- Limits: scripts run without asking each time, for at most 60 seconds; at most 5 reads or runs and 10 writes per question; tool results passed to the model are cut at 20,000 characters. 停止 also stops a running script. If the endpoint does not support function calling, the page says so; choose an instructions-only skill or another model.
- Choosing a skill with scripts lets them run as you, with access to whatever you can read and write. Install only skills you trust. Script output is sent to the endpoint.

Bundled skills:

| Name | Shown as | Purpose | Scripts |
| --- | --- | --- | --- |
| `summarize-meeting` | 会议纪要 | Meeting transcript or notes → date, attendees, key points, decisions, action items, open questions | none |
| `doc-compare` | 文档对比 | Line-by-line comparison of two picked files: additions, deletions, changes and a summary of what really changed, with an optional side-by-side HTML report | `scripts/compare.py` |
| `office-gen` | 生成 Word 与 Excel | Turns prepared content into docx or xlsx files that can be saved | `scripts/make_docx.py` (Markdown → docx), `scripts/make_xlsx.py` (JSON → xlsx) |
| `prompt-optimize` | 提示词优化 | Rewrites a draft prompt into a short, clear, numbered one | none |
| `clarify-needs` | 需求澄清 | Asks one question at a time until a vague task is clear, sums up the needs and acts once they are confirmed | none |
| `skill-create` | 创建 skill | Drafts a new skill with you, then writes `SKILL.md` and reference text and packs `<name>.zip` for you to install | `scripts/pack_skill.py` (checks and packs; .md and .txt only, no scripts) |

The bundled scripts use only the Python standard library and also run from a terminal (pass files through the variables above), with `--help` and `--log-level`. `summarize-meeting` is copied unchanged from [phuryn/pm-skills](https://github.com/phuryn/pm-skills) (MIT License); its folder holds that licence and `UPSTREAM.md`.

The bundled skills follow Anthropic's Skill authoring best practices: the description says what the skill does and when to use it, with the words that trigger it; the instructions hold only what the model would not know; error-prone steps are scripts that are run, not read; fixed formats get a made-up example; key steps say how to check and what to change, and script errors say what to do. `skill-create` asks the same of new skills. `summarize-meeting` stays as copied; its web search and save-to-file steps are turned into answering directly by the skill introduction. To compare a skill before and after a change, run `python3 tests/skill_eval_run.py --base URL --model NAME [--key KEY] [--skill NAME] [--out report.md]` (or set `ASK_EVAL_BASE`, `ASK_EVAL_MODEL`, `ASK_EVAL_KEY`) on both versions; each scenario starts a temporary copy of the tool and leaves your settings and knowledge base alone.

## Server and exit

On first double-click the file manager may ask whether to trust or run the entry; allow it, or tick "allow executing as program" under Properties → Permissions. To put it on the desktop, use the file manager's "send to desktop" action or `ln -s "$PWD/资料管家.desktop" ~/Desktop/`; do not copy it, because a copy cannot find the program and says so when double-clicked. Up to 2.12 the entry was called `双击运行.desktop`; a desktop link to that name stops working after upgrading and has to be made again from the tool folder.

Double-clicking opens the page in an app window of a Chromium-family browser (`--app`, no address bar) when one is found, including Chinese Chromium-based browsers such as Qianxin, 360 and UOS, which are also located through their desktop files when not on PATH; otherwise in a normal window of the default browser.

The server listens on 127.0.0.1 only, on port 47821 by default (change it with `--port` or `"port": <number>` in `config.json` in the storage location). Its address carries a token that is created on first start and kept as `token` in the storage location (mode 600), and Host and Origin are checked, so the address stays the same across restarts and can be bookmarked or pasted into any browser; 复制网址 ("copy address") in the footer copies it. `--new-token` replaces the token and invalidates the old address (refused while the tool is running). Starting the tool while it is already running from the same folder and version only opens a page; when the port is held by this tool running from another folder or another version (for example after the tool folder was moved or replaced), that one is asked to quit and this start takes over once the port is free within 10 seconds, or a system dialog asks to try again later if it is busy; if another program holds the port, it says so and suggests `--port`. The server exits 5 seconds after the last page closes, or at once when you press 退出 ("quit"), which also closes the open pages; an answer being written, inclusion and organising stop with it (waiting at most 15 seconds) and resume on the next start. Without any page ever connecting it exits after 30 minutes (`--idle-timeout`, 0 for never). The log is `ask_local_files.log` next to the program, or in `~/.cache/ask-local-files/` when that folder is not writable.

Command line: `python3 ask_local_files.py [--no-browser] [--no-app] [--port N] [--idle-timeout SECONDS] [--data-dir DIR] [--print-url] [--new-token] [--upgrade ZIP_OR_FOLDER [--yes]] [--rollback [--yes]] [--version] [--log-level DEBUG|INFO|WARNING|ERROR]`. `--no-browser` only prints the address, `--no-app` opens a normal window of the default browser, `--port` sets the port, `--idle-timeout` sets how long to wait with no page and nothing running before exiting (default 1800, 0 for never), `--print-url` prints the address without starting the server, `--new-token` replaces the token and prints the new address, `--data-dir` changes the storage location (see Knowledge base), `--upgrade` and `--rollback` are described under [Upgrade](#upgrade), and `--version` prints the version. Each prints one line `网页界面：<address>` on standard output. The default log level is WARNING, and `LOG_LEVEL` overrides it.

Tests: `python3 -m unittest discover -s tests`. With Playwright installed, also run `node --test tests/ui.test.js`.

## Upgrade

Unpack the first release into a folder you choose and will not move, and put the desktop link to `资料管家.desktop` there. Every later version replaces that folder's contents in place, so the path, the desktop link and the page address stay the same.

1. Get the new zip (or unpack it and use the `ask-local-files` folder it contains).
2. On the page, press 升级 ("upgrade") at the top right and pick or drop the zip or folder. The page shows current version → new version, the changelog entries between them, the files that will be kept and any extra files; a downgrade or reinstall is called out.
3. Press 升级到 vX.Y ("upgrade to vX.Y"). Stage text is shown and the buttons are disabled meanwhile; an answer being written (including a skill script) or a manual knowledge base organising run is waited for; the wait shows what it is waiting for and can be cancelled with 取消等待 ("stop waiting"), which leaves the tool folder unchanged. Automatic inclusion and idle-time organising stop and resume on the new version. The server then restarts on the new version with the same port and token, and the page reconnects.

From a terminal: `python3 ask_local_files.py --upgrade new.zip` shows the same check and asks for confirmation (`--yes` skips it); the tool must not be running.

- Kept files: those listed in `upgrade-keep.txt`, namely `data-dir.txt` (only present after the storage location was changed) and `ask_local_files.log`. The knowledge base, settings and token live in the storage location, not in the tool folder, so an upgrade does not touch them.
- Extra files: files in the tool folder that are neither in the keep list nor part of the new version are listed before upgrading; they are not deleted but stay with the previous version.
- Previous version: the old folder becomes the hidden folder `.ask-local-files.上一版` next to it; only one is kept. 退回上一版 ("roll back") on the page or `python3 ask_local_files.py --rollback` swaps it with the current version; doing it again swaps back.
- Nothing is changed, and the reason is shown, when the package is not this tool (its top folder is not `ask-local-files`), its version cannot be read, the program or desktop entry is missing, it contains `..`, absolute paths, symbolic links or device files, it unpacks to more than 200 MB or 5000 entries, or the folder holding the tool folder is not writable. A failure part-way restores the previous state.
- A zip uploaded by the page is written only to the system temporary directory and removed afterwards; a picked folder is packed into a zip by the page first.
- Upgrading from 2.14 or earlier, which has no upgrade function: unpack the new version elsewhere and run `python3 <unpacked folder>/tool_upgrade.py --tool-dir <current tool folder> --upgrade new.zip` once; later upgrades work as above.
